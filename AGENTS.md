# Rules

1. Do not add unnecessary information to the README.md file. If a new language is added, for example, simply list it in the existing table. Implementation details do not belong in the README.md file.
2. Keep it simple, stupid. Code should be easy to read and understand. Avoid complex structures and unnecessary abstractions.
3. Use clear and descriptive names for variables, functions, and classes. Avoid abbreviations and single-letter names.
4. Only write comments where strictly necessary and remember that comments should explain why something is done, not what is done.
5. DO NOT use inline tests. Put them in the `tests` folder.
6. Keep tests short, simple and reusable. If you believe a specific behavior needs to be tested, write the test before implementing the behavior.
7. Always use atomic, semantic commits. Each commit should represent a single, logical change to the codebase. Avoid bundling multiple unrelated changes in a single commit.
